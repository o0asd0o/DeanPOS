# 13 — Pull the shared parts from shadcn, unmodified

**Status:** ready-for-agent

## What to build

The five shared parts ADR-0013 puts in scope, **pulled with the shadcn CLI and committed as they
arrive**. No re-skinning here — that is issue 14, deliberately separate.

The split is the point. A vanilla commit followed by a re-skin commit means the diff between them is
exactly *our* changes, reviewable on its own and re-derivable when a component is regenerated later.
Record 007 already named that reviewable-regeneration diff as the reason `packages/ui/src/components/`
is exempt from code-standards rule 2. Merging pull and re-skin into one commit destroys it.

**Components are pulled, never authored.** `shadcn` 4.16.1 and a configured `components.json` are
already in `packages/ui`; `button` and `sheet` came from them.

## What is in scope, and why each

| Part | Pulled as | Proven by |
| --- | --- | --- |
| Shell sidebar | `sidebar` | every back-office mock; `design/lofi/README.md` says the shell is built once and inherited |
| Card surface | `card` | every mock with a panel |
| Status badge | `badge` | order and drawer states across `reporting` and `checkout` |
| Table | `table` | the nine reports are all filter-strip-plus-table |
| Filter strip | `tabs`, `select`, `input` | same |

**The filter strip is not a component.** No shadcn equivalent exists; it is a composition of the
three primitives above. Do not invent one here, and do not expect issue 14 to either — 14 skins the
three primitives and is explicitly forbidden from assembling them. **Area 7 composes the strip**, on
the first real report screen, and decides there whether it ever deserves extraction.

## What is deliberately not pulled

- **`command`** — the reference's `⌘+Space` palette. That shortcut is Spotlight on macOS, and
  `apps/pos` runs on a tablet with no keyboard. ADR-0013 rejects it.
- **Stat tiles and the accuracy gauge** — no shadcn equivalent, and no DeanPOS mock asks for either.
- **`dropdown-menu`, `collapsible`, `alert`, `separator`, `skeleton`, `sonner`** — record 007 declined
  each with a reason. Nothing in this issue changes those reasons.

## Acceptance criteria

- [ ] `sidebar`, `card`, `badge`, `table`, `tabs`, `select`, `input` present under
      `packages/ui/src/components/`, generated by the CLI, and re-exported from
      `packages/ui/src/index.ts`.
- [ ] **No `@tanstack/react-table`.** shadcn's sortable data table is a recipe built on it; the CLI's
      `table` is styled markup with no sorting, and that is what lands here. Record 007's import ban —
      *"No file under `packages/ui/` may import from `contract`, `schemas`, `backend`, `@orpc/*`, or
      `@tanstack/*`"* — is upheld, and ADR-0013 accepts the resulting duplication: each app builds
      sorting on top.
- [ ] **`sidebar` arrives with transitive parts** — it is built on `sheet`, and typically also pulls
      `tooltip`, `separator`, `skeleton`, and `input`. Several of those are ones record 007 declined.
      Accepting them as `sidebar`'s dependencies is fine; **arriving without anyone noticing is not.**
      The build report lists every file the CLI created or overwrote, and flags any that record 007
      had declined, so the next area does not re-argue them from scratch.
- [ ] **`shadcn add` must not alter the palette.** It injects its own colour tokens into the file
      named by `components.json`'s `tailwind.css` — which is `src/theme.css`, the file issue 11 just
      rewrote. Review that diff on every pull and revert every token change. If OKLCH values land,
      `contrast.test.ts` cannot parse them and the palette silently stops being verified.
- [ ] `contrast.test.ts` green, including the expected-token-name assertion issue 11 adds. That
      assertion is what makes "the CLI did not change the palette" a checkable claim rather than a
      reported one — the older behaviour only verifies that whatever is declared is covered, so an
      injected or deleted token could pass unnoticed.
- [ ] If `shadcn add` cannot resolve the workspace, use the fallback issue 05 already proved:
      `shadcn add --dry-run --view` and transcribe the CLI's own `new-york` output byte-for-byte. Do
      **not** hand-author a component that resembles one.
- [ ] **Generated against Radix, not Base UI.** Record 007 chose `--base radix` deliberately and
      names the newer Base UI default as the risk; `button` and `sheet` both import from `radix-ui`.
      Assert it rather than assume it: no `@base-ui/*` import or dependency anywhere in the package,
      and the pulled parts import `radix-ui` where they need a primitive. A silent generator-default
      change ships a second UI runtime and an unrecorded dependency in one commit.
- [ ] Nothing in the package is domain-aware. No pulled or re-exported part knows what an Order, a
      DrawerSession, or a Tenant is.
- [ ] **The generated files are not edited — including their focus classes.** Every component pulled
      here ships with stock shadcn's `outline-none focus-visible:ring-[3px]`, which is the exact
      opt-out that produced issue 05's blocking finding. It is stripped in issue 14, not here, and
      the reason is the one this whole issue exists for: an edit in this commit destroys the vanilla
      baseline that makes issue 14's diff reviewable. Nothing consumes these parts until issue 15, so
      the defect is never reachable in a shipped surface.
      **Name it in the build report** as a known defect handed to issue 14, so a reviewer does not
      read the silence as an oversight.
- [ ] `check` and `test` pass across the repository.

## Comments

_Written from the `/grill-with-docs` session of 2026-08-02. Decision: `docs/adr/0013`._

**Expect `sidebar` to be large** — a state provider, cookie-persisted collapse, a `Ctrl+B` shortcut,
a rail, and roughly twenty sub-parts, most of which DeanPOS will not use. ADR-0013 chose to pull it
anyway rather than hand-author a nav shell. Leave the unused parts alone in this issue; stripping is
a judgement call that belongs with the re-skin, where the shape is known.

The `Ctrl+B` shortcut and the cookie are harmless on a terminal: the collapse state is device-scoped,
which is the correct scope for a shared device anyway.

**This issue does not touch either app.** `AppShell.tsx` and `Nav.tsx` keep using what they use until
issue 15.
