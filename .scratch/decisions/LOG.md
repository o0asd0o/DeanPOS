# Decision log

One line per record. The files in this directory are the numbering authority; this index is regenerable.

- [001: The project stores data in PostgreSQL](001-database-engine.md) — seeded at setup, Stakes: high
- [002: Money gets property tests from `fast-check`, and nothing else is added](002-property-testing-for-money.md) — `fast-check@4.9.0`, devDependency-only, catalog-pinned; no `@fast-check/vitest`, Stakes: high
- [003: Every Delta on a line is measured against the item's own price, and only one can be a multiplier](003-delta-composition.md) — ratifies the built arithmetic (contributions summed against the base, order-independent, exact); adds a one-multiplier-per-OrderLine guard in `catalog` and `checkout` that keeps the rule free to reverse, Stakes: high
- [004: Kysely talks to PostgreSQL through `pg`, the same driver the sibling project runs](004-postgres-driver.md) — `pg@8.22.0` dependency + `@types/pg@8.20.3` devDependency in `packages/backend` only, no catalog pin, Kysely's built-in `PostgresDialect`; adopts ApxDenta's production Bun setup; transaction-affinity guaranteed by Kysely's driver, so area 2 uses `set_config(..., true)`; no `pg-native`, Stakes: high
- [005: The Prisma commands become root scripts, and the root `.env` reaches them](005-prisma-command-scope-and-env.md) — resolves the ADR-0004 / ADR-0008 / issue-03 contradiction: `prisma` stays in `packages/backend` only, and root `codegen`/`migrate`/`migrate:status` scripts scope into it with `vp exec -F backend`; the three `ORC2_*_CMD` values become `vp run -w <script>`; the migrate scripts source the root `.env` because Prisma never searches parent directories; a root `prepare` hook makes `vp install` alone reach a green gate. ADR-0008 and record 004 untouched; ADR-0004 amended, Stakes: high
- [006: The oRPC packages, and zod 4 without the zod integration package](006-rpc-and-validation-dependencies.md) — `@orpc/contract` + `@orpc/client` in `packages/contract`, `@orpc/server` + `hono@4.12.33` in `apps/api`, `@orpc/tanstack-query` in both front ends, all `@orpc/*` at `1.14.13` and catalog-pinned as a lockstep family; `zod@4.4.3` catalog-pinned in `schemas`/`contract`/`backend`; **no `@orpc/zod`** (it is an OpenAPI converter and DeanPOS publishes no OpenAPI document — removing it removes the only zod-major constraint) and **no `@hono/*` adapter** (oRPC's own `@orpc/server/fetch` covers it); all `dependencies`, none dev; client built once in `packages/contract` as a factory taking `fetch`, so the in-process `app.request()` seam has a single injection point; the missing-procedure compile error verified from oRPC's type source, not its docs, Stakes: high
